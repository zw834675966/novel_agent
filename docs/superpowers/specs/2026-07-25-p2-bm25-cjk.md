# P2 — Zero-dependency BM25 with CJK support

Date: 2026-07-25
Status: implemented (in tree, tests green)
Scope: `src/vocab/loader.rs` ranking path only

## Problem

`candidates_ranked_limited` previously scored candidate `text`+tags with
whole-term substring TF, which under-ranked CJK queries: multi-character names
like 「宝玉」/「紫菱洲」 rarely substring-match candidate text, so relevant
candidates tied at zero even when they shared characters.

## Design

Replace substring TF with a zero-dependency BM25 (no new crate):

- **Tokenizer** `tokenize_for_bm25`: CJK continuous runs (≥2 chars) -> overlapping
  bigrams; lone CJK char -> unigram; ASCII alnum run -> one lowercased word.
- **Query expansion** `expand_query`: each trimmed term ≥2 chars stays whole
  (atomic name) plus its tokenized sub-tokens (dedup, order-preserving) — gives
  exact hits AND partial bigram overlap.
- **Doc model** `doc_bag_counts`: multiset token bag of `text` + each tag (exact
  + tokenized). TF = multiset count; `dl` = bag token count; `avgdl` = mean.
- **Scoring** `Bm25Scores::build`: IDF `ln((n-df+0.5)/(df+0.5)+1)`, BM25
  `idf * tf*(k1+1) / (tf + k1*(1-b+b*dl/avgdl))`, k1=1.2, b=0.75.
- Empty query -> BM25=0, ranking falls back to selected-tag + name-tag boosts,
  then SENSES order + id (stable, deterministic).
