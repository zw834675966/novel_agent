# 平台 AI 文检测/治理逆向 → novels 为何仍有 AI 感

> Superpowers research · 2026-07-22  
> 目标：用 DeepSeek Flash + 蒸馏语料写出**读者/平台视角下**「无 AI 感」正文——先定位番茄等如何治 AI 文，再逆向映射到当前栈的泄漏口。  
> 证据：联网检索 + 晋江公告原文 + 行业报道；内部 `cargo run` 真实 DeepSeek 输出。  
> 源日志：`{SCRATCH}/platform-ai-detection-sources.md`（会话 scratch；可审计 URL 见附录）  
> **非目标**：本文件不改代码、不优化「过 GPTZero 分数」、不做 style-transfer 主路径。

## 1. 平台如何「检测 / 治理」AI 写小说（可操作清单）

> 诚实前提：各平台**几乎不公开**分类器权重或固定 API 分数。公开面是 **政策 + 质量代理 + 人工/读者闭环 + 不稳定的鉴定软件**。把「检测」窄化成单一分数会误导工程优先级。

### 1.1 番茄小说（字节 · 免费网文主战场）

| 信号类型 | 公开/报道行为 | 工程含义 |
|----------|----------------|----------|
| **低质/AI 粗制滥造** | 2025 起多轮治理：滥用 AI **批量生成**、严重缺乏原创性列为严禁低质类；报道称单月处置低质书十余万量级（拒签+下架） | 打击的是**流水线量产 + 无可读性**，不是「用过模型」本身 |
| **签约审查代理** | 2025-04-07《签约流程优化》：拒签全篇/大篇幅「**情节叙事不清、结构混乱、转折生硬、逻辑割裂**」；多次低质则失去签约机会 | **叙事连贯与推进**是第一道闸，不是字面「AI 率」 |
| **水文 / 注水代理** | 2025-02 起封禁恶意水文账号；全勤门槛上调（报道：听读收益门槛提高）抬高 AI 刷量经济 | **无意义环境堆砌、原地打转、字数刷更** = 平台侧 AI 等价物 |
| **算法分发** | 免费 + 推荐驱动：AI 文易占首秀名额 → 平台被迫用门槛+审核回收 | 读者完读/停留差也会间接杀书 |
| **合规标识** | 上传时「是否使用 AI」勾选；对齐《人工智能生成合成内容标识办法》（2025-09 施行） | 与「文风无 AI 感」正交：合规声明 ≠ 过审质量 |
| **辅助工具矛盾** | 平台自带扩写/续写/大纲灵感，同时打击黑灰产批量 AI | **允许辅助、打击低质与量产**；结果论 |

行业归纳的 **AI 文内生三缺陷**（上海观察者等 2025 综述，与番茄治理话术同向）：

1. **长线逻辑乱**：前后矛盾、设定漂移  
2. **内容注水**：无效环境/场景描写、对话硬、情节不推  
3. **文风机械**：杂糅腔、生僻高级词、平滑无个性  

### 1.2 晋江文学城（付费 · 明确分级政策）

官方试运行公告（2025-02-17，站长 iceheart，[晋江论坛](https://bbs.jjwxc.net/showmsg.php?board=17&id=2214182)）：

| 维度 | 规定摘要 |
|------|----------|
| **允许 AI** | 文字型-**校对**；创意型-**要素**（书名/人名等）；创意型-**粗纲**（一两句梗概、无七要素细纲） |
| **禁止 AI** | 描写级润色（加环境/心境等）、叙事级情节推进、细纲级七要素；影响「人作为写作主体」 |
| **「检测」怎么做** | **不信任**单一鉴定软件（站长自述 DeepSeek 判其原创诗 100% AI）；有「铁证」（未删提示词）直接按级处罚；无铁证则读者测软件 **>60% 可疑** 可举报，站方再跑软件，**有反例则举报无效** |
| **罚则** | 锁章、黄牌 1 月、永久禁榜；V 文退订；须回退至过 AI 前原稿 |

→ 晋江逻辑：**原创主权 + 读者举报闭环 + 软鉴定**，不是黑盒分数 API。

### 1.3 起点/阅文、七猫、纵横（对照）

| 平台 | 信号 |
|------|------|
| **起点系** | 编辑强把关；编辑社区交流用鉴定工具筛稿；纯 AI 难过签/难赚订阅；仍见「提示词残留」铁证下架个案 |
| **七猫** | 编辑向作者「拒收 AI 文」类声明（行业报道）；较早要求 AI 使用标注 |
| **纵横** | 生成式 AI 使用情况标注（监管对齐） |
| **共性** | **读者厌恶**（付费尤甚）+ **编辑经验特征**（套路动作、苍白心理、同质化）+ **批量/水文运营指标** |

### 1.4 监管与「产品检测器」边界

- 《人工智能生成合成内容标识办法》：平台须提供标识与用户声明——**合规层**。  
- 商业「小说 AI 率」工具（第三方）波动大；晋江已书面承认误伤/漏网。  
- **结论：** 逆向工程应优先对齐 **平台质量代理 + 读者 AI 味特征**，而非刷某个检测分数。

## 2. 逆向映射表：平台信号 → novels 必须避免/对冲 → 当前可观测泄漏

| # | 平台/读者信号 | 无 AI 感管道必须 | novels 现状（2026-07 实码+真跑） | 泄漏判定 |
|---|---------------|------------------|-----------------------------------|----------|
| P1 | 情节叙事不清 / 转折生硬 / 逻辑割裂（番茄签约话术） | 长线状态一致：角色记忆、plot、场景因果可对账 | `plot_development.reason` + `new_memory` 仍为 **LLM 自由文本**（仅限长+剥「因此/于是…」） | **主泄漏** |
| P2 | 注水：无效环境描写、情节不推（AI 文三缺陷之二） | 描写服务 beat 推进；禁止堆感官清单 | `assemble` **固定 8 类顺序**拼接 `vocab.text` + action；真跑正文「血迹血腥味侦探推开…」 | **主泄漏（清单感）** |
| P3 | 同质化 / 批量黑灰产 | 场景贴戏选材；禁跨书串味、禁日更刷量形态 | BM25 已抬稀有角色/尸体等贴戏 quote；但 **红楼尸体句 + 甄嬛人影句** 可同段混用 | **中（声口/书源混拼）** |
| P4 | 文风机械、平滑、万能修饰 | 灵魂句 **verbatim**；骨架短；禁通顺泛因果 | 描写层 ID 注入 **已对齐**；action 仍可「低声道/俯身查看」类 **通用网文壳** | **中** |
| P5 | 铁证：提示词残留、工具套话 | 输出过滤「以下是为您润色…」 | 无专门 strip；依赖 LLM 契约 | **低（未现）** |
| P6 | 鉴定软件 / 60% 举报阈值 | 提高 burstiness；减少句长均匀与连接词 | 原著 quote 提高困惑度（有利）；**硬拼降低自然节奏**（不利） | **中** |
| P7 | 读者付费厌恶「AI 参与叙事」 | 叙事主体在人：骨架/选择可模型，**情节与动机不可整段生成** | 叙事 beat 的 action **整句由 DeepSeek 生成** | **主泄漏（晋江叙事级）** |
| P8 | 合规标识 | 产品层声明合成比例 | 引擎无声明字段 | **产品外** |
| P9 | 完读/停留代理 | 节奏、钩子、信息密度 | 单场景 demo 未测长线完读 | **未测** |

### 2.1 真实 DeepSeek 跑次证据（机制赢 vs 读者仍嫌 AI）

环境：`DEEPSEEK_API_KEY` 加载 · 词库 base+187 distilled · total≈13889 · 场景「古宅发现一具尸体」

| KPI | Run A | Run B | 含义 |
|-----|-------|-------|------|
| quote_density | 0.51 | 0.63 | **机制赢**：过半字符是原著 quote |
| unverified_quotes | 0 | 0 | **机制赢**：注入可回源 |
| stripped/rejected | 0 | 0 | ID 闭集工作 |

**读者向仍 AI 的段落纹理（拼装结果特征）：**

```text
血迹血腥味侦探推开古宅房门，停下脚步。
金桂的母亲此时势孤……只见满脸黑血，直挺挺的躺在炕上，便叫哭起来。
侦探走到炕前，俯身查看。
修竹千竿之后有个人影一闪侦探直起身，转向窗外。
```

对照平台信号：

- **P2 注水/清单**：短词 `血迹`+`血腥味` 无标点硬贴 → 「排版/清单感」类低质观感。  
- **P3 混源**：红楼夏金桂尸景 + 甄嬛竹影句 → 声口/世界观不自洽（编辑一眼假）。  
- **P1/P7**：action「侦探推开/俯身/转向」是 **Flash 生成骨架**，通顺但套路；memory/plot reason 仍是「必然怀疑/重要线索」式 **AI 因果说明文**。  
- **quote density 高 ≠ 无 AI 感**：平台拒的是「不可读/不连贯/像量产」，不是「原句占比不足」。

## 3. 差距诊断：为何还达不到目标

### 3.1 已赢的机制（不要回退）

| 能力 | 为何对平台/读者有用 |
|------|---------------------|
| 蒸馏子串校验 + 程序注入 | 避免描写层 paraphrase → 抗「平滑 AI 腔」主路径正确 |
| BM25 + 声口 tag 加权 | 贴戏 quote 进 cap（真跑选中尸体场景 atmosphere） |
| density / provenance KPI | 可审计「灵魂含量」；非终点 |
| text_guard 剥因果套话 | 部分对齐 P1；覆盖词表仍窄 |

### 3.2 仍达不到的根因（按平台逆向排序）

1. **拼装纹理 ≠ 小说节奏（P2/P6）**  
   固定八类拼接制造「素材表感」；真人网文是 **省略、错落、对话打断**，不是感官字典遍历。

2. **叙事级仍由 Flash 写（P7 晋江红线 / P1 番茄）**  
   蒸馏只填描写槽；**故事推进句**仍是模型概率句 → 读者归类为 AI 叙事。

3. **memory / plot 自由文本（P1）**  
   角色记忆与情节 reason 可写「气氛悲凉肃杀」类二次 AI 描写，绕过 ID 注入。

4. **跨书 quote 混拼（P3）**  
   无 `source_book` 硬约束 → 红楼梦腔 + 甄嬛传腔同段 = 同质化杂糅的镜像。

5. **成功指标错位**  
   团队 KPI：density、unverified=0。  
   平台/读者 KPI：连贯、推进、声口一致、不像量产。  
   **指标未对齐 → 机制赢、目标输。**

6. **DeepSeek Flash 能力边界**  
   短 action 仍套路；长线一致性本模型档位弱——填充不能单独解决长篇逻辑。

### 3.3 逆向下一刀（禁止再堆 style-transfer）

| 优先级 | 动作 | 对应平台信号 | 验收代理 |
|--------|------|--------------|----------|
| **N1** | **拼装节奏**：标点/连接策略；允许省略感官类；禁「短词连续裸贴」 | P2 注水/清单 | ✅ **已落地** `join_quotes_with_rhythm` / `join_desc_action` |
| **N2** | **书源/声口隔离**：候选与 assemble 按角色绑定书源或 name tag；禁跨书同 beat | P3 同质杂糅 | ✅ **已落地** assemble 内 hlm/zhz 多数源；base lemmas kept |
| **N3** | **action 模板化/极短**：舞台提示级（主语+动作+对象），禁心理/环境；ID 化动作库 | P7 叙事级 AI | ✅ **已落地** `StructuredAction` enum with 32 kinds + render/sanitize |
| **N4** | **memory/plot 结构化**：reason 枚举或短槽；禁开放抒情 | P1 逻辑/说明文因果 | ✅ **已落地** `PlotReasonSlot` 枚举 + PlotDevelopment 集成 + JSON 持久化 |
| **N5** | **长线状态机**：设定表 + 矛盾检测（前后人设/尸体状态） | P1 长线割裂 | 跨场景一致性抽检 |
| **N6** | **读者向评测集**：固定 10 场景盲评「像 AI 量产 / 像人写」；完读代理 | 平台结果论 | 非 density 单一 KPI |
| **Avoid** | CAT-LLM/全文润色主路径；唯检测器刷分 | 晋江已证检测不稳 | — |

## 4. 一句话结论

**平台「检测」实质是：低质/水文/叙事割裂/量产代理 + 读者举报 + 弱鉴定软件，而不是公开的稳定 AI 分数。**  
novels 已用蒸馏填充赢了「描写层防改写」，真实 DeepSeek 下 density 0.5–0.6、回源 0；**仍败在拼装清单感、跨书串味、Flash 写叙事骨架与 memory/plot 自由因果——这些正是番茄签约话术与晋江「叙事级禁止」所针对的纹理。**  
下一刀应是 **节奏化拼装 + 声口/书源隔离 + 压叙事自由文本**，不是再堆风格迁移。
